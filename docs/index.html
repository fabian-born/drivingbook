Das Fahrtenbuch, das auf deinem Server läuft.

drivingbook erfasst Fahrten in Sekunden am Smartphone, rechnet Strecken automatisch aus und liefert zum Jahresende ein sauberes PDF-Fahrtenbuch. Dazu gibt es den Vergleich zwischen 1-%-Regel und Fahrtenbuch. Selbst gehostet mit Docker, ohne Cloud und ohne Abo.

Funktionen

Alles, was ein Fahrtenbuch für Dienstwagen oder Firmenfahrzeuge braucht, von der schnellen Erfassung unterwegs bis zur Auswertung für die Steuererklärung.

Schnell erfassen

km-Stand, Ziel und Fahrtart eingeben und speichern. Der Zeitpunkt wird automatisch gesetzt, der GPS-Knopf füllt die aktuelle Adresse ein.

Offline-fähig (PWA)

Als App auf dem Homescreen installierbar. Ohne Netz erfasste Fahrten werden gesendet, sobald wieder eine Verbindung besteht.

Drei Fahrtarten

Geschäftlich, privat und Arbeitsweg werden getrennt gezählt und in allen Auswertungen farbig unterschieden.

Mehrere Fahrzeuge

Das aktive Fahrzeug wechselst du in der Navigation. Alle Seiten zeigen dann nur dessen Fahrten.

1-%-Regel oder Fahrtenbuch?

Aus Listenpreis und Jahreskosten berechnet die Auto-Info, welche Methode günstiger ist. Mit Grenzsteuersatz auch die geschätzte Ersparnis.

Prüfung vor der Steuererklärung

Eine Ampel meldet km-Rückschritte, Lücken ohne Einträge, auffällig lange Strecken und Koordinaten statt Adressen.

Nachvollziehbar

Jede Anlage, Änderung und Löschung landet mit altem und neuem Stand im Änderungsprotokoll. Das ist wichtig für ein ordnungsgemäßes Fahrtenbuch.

Export & Sicherung

CSV und PDF pro Jahr, dazu Sicherungen einzelner Fahrzeuge oder des ganzen Kontos als JSON. Beim Wiederherstellen wird nur ergänzt, nie überschrieben.

API & Home Assistant

Mit einem API-Token trägt z. B. Home Assistant Fahrten automatisch aus dem km-Sensor des Autos ein.

Hell & dunkel

Die Oberfläche folgt automatisch der Systemeinstellung, lässt sich aber auch fest einstellen.

Für Admins

Benutzerverwaltung, Aufräumen doppelter Fahrten und nicht zugeordneter Einträge, tägliches Datenbank-Backup und ein Skript zum Zurücksetzen von Passwörtern.

Sicher

JWT-Login, gehashte API-Tokens, Rate-Limits für Login und Registrierung. Die Registrierung lässt sich abschalten.

Rundgang

Alle Screenshots stammen aus der App mit Demo-Daten. Ein Klick öffnet das Bild in voller Größe.

Neue Fahrt: gebaut für das Smartphone

Die wichtigste Seite ist die, die du im Auto öffnest. Große Eingabefelder, drei farbige Knöpfe für die Fahrtart und ein Speichern-Knopf über die ganze Breite.

  • Der letzte km-Stand des Fahrzeugs steht als Vorschlag im Feld.
  • Der GPS-Knopf ermittelt die aktuelle Adresse über OpenStreetMap.
  • Ist der km-Stand kleiner als bei der vorherigen Fahrt, fragt die App nach.
  • Unterwegs ohne Netz? Die Fahrt wartet in einer Warteschlange und wird später gesendet.

Dashboard

Der Überblick über das laufende Jahr: km im aktuellen Monat, im Jahr und im Schnitt, die Aufteilung nach Fahrtart und ein Diagramm der gefahrenen km je Monat.

  • Darunter steht die Monatsübersicht mit Start- und End-km.
  • Die Seite aktualisiert sich selbst, wenn du in die App zurückkehrst.
  • Eine Erinnerung erscheint, wenn die letzte Sicherung über 30 Tage alt ist.

Fahrten anzeigen & bearbeiten

Alle Fahrten eines Monats, filterbar nach Fahrtart. Ziel, km-Stand, Fahrtart und Zeitpunkt lassen sich direkt in der Liste ändern. Die Strecke zur vorherigen Fahrt rechnet die App selbst aus.

  • Export des Jahres als CSV oder PDF.
  • Das Protokoll zeigt alle Änderungen und Löschungen des Jahres.
  • Auf dem Smartphone wird aus der Tabelle eine Kartenansicht.

Jahreshistorie

Abgeschlossene Jahre auf einen Blick: Gesamt-km, Aufteilung, Verlauf je Monat und die Monatstabelle mit Anteilen je Fahrtart. Die Seite ist druckfertig, und der CSV-Export liegt direkt daneben.

Auto-Info: 1-%-Regel oder Fahrtenbuch?

Pro Fahrzeug trägst du Bruttolistenpreis, Antrieb und die Jahreskosten ein. drivingbook vergleicht dann den geldwerten Vorteil nach 1-%-Regel (inklusive Arbeitsweg) mit dem Privatanteil laut Fahrtenbuch und zeigt, bis zu welchem Privatanteil sich das Fahrtenbuch lohnt.

  • Berücksichtigt Verbrenner, Hybrid und E-Auto (0,25 % / 0,5 %).
  • Die Prüfung vor der Steuererklärung zeigt als Ampel, ob alles vollständig ist.
  • Fahrzeugverwaltung, Code für API und Home Assistant sowie die Sicherung einzelner Fahrzeuge.

Vereinfachte Schätzung, keine Steuerberatung.

Ausschnitt. Das ganze Bild öffnet sich per Klick.

Konto & Sicherung

Unter Profil → Konto sicherst du alle Fahrzeuge mit Fahrten, Jahreskosten und Änderungsprotokoll in eine JSON-Datei. Die Tabelle zeigt, wann zuletzt gesichert wurde und wie viele Änderungen seitdem dazugekommen sind.

  • Beim Wiederherstellen wird nur Fehlendes ergänzt, vorhandene Daten bleiben unberührt.
  • Ein gelöschtes Fahrzeug wird mit seinem Code neu angelegt.
  • Hier findest du auch Passwort und API-Tokens.

Dunkelmodus

Die Oberfläche wechselt automatisch mit der Systemeinstellung, auch im laufenden Betrieb. Farben und Diagramme sind für beide Modi abgestimmt. Gedruckt wird immer hell.

Home Assistant & API

Unter Profil → Konto erzeugst du ein API-Token. Damit kann jedes System Fahrten eintragen, zum Beispiel Home Assistant beim Abstellen des Autos mit dem aktuellen km-Stand.

Ohne vehicle_code landet die Fahrt beim Standard-Fahrzeug. Den Code eines Fahrzeugs findest du in der Auto-Info. Passt der km-Stand nicht zu den Nachbarfahrten, antwortet die API mit 409. Mit "force": true wird trotzdem gespeichert.

Eine vollständige Home-Assistant-Konfiguration (rest_command und Automation) steht in HA_integration.txt.

# Fahrt per API-Token eintragen
curl -X POST https://fahrtenbuch.example.de/api/trips \
  -H "Authorization: Bearer <API-TOKEN>" \
  -H "Content-Type: application/json" \
  -d '{
    "odometer_km": 65230,
    "destination": "Kunde Muster GmbH",
    "trip_type": "business",
    "timestamp": "2026-09-26T08:30:00Z",
    "vehicle_code": "4GAQAB"
  }'

# trip_type: business | private | commute

Installation

drivingbook besteht aus drei Containern: PostgreSQL, dem Node.js-Backend und einem nginx-Frontend. Du brauchst nur Docker mit Docker Compose.

  1. Repository holen

    git clone https://github.com/fabian-born/drivingbook.git
cd drivingbook

  2. Konfiguration anlegen

    Mindestens ein starkes DB_PASSWORD und ein JWT_SECRET mit 32 oder mehr Zeichen setzen.

    cp .env.example .env
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"

  3. Starten

    docker compose up -d --build

    Das Frontend läuft auf http://localhost (Port über FRONTEND_PORT). Datenbankschema und Admin-Benutzer legt das Backend beim ersten Start selbst an.

Gut zu wissen

Ohne ADMIN_PASSWORD wird beim ersten Start ein Zufallspasswort erzeugt und einmalig im Log ausgegeben (docker compose logs backend).

ALLOW_REGISTRATION=false schaltet die öffentliche Registrierung ab. Neue Benutzer legt dann der Admin an.

Ein zusätzlicher Container sichert die Datenbank täglich nach backend/data/backups (Aufbewahrung über BACKUP_KEEP_DAYS).

Admin-Passwort vergessen? docker exec -it fahrtenbuch-backend node scripts/reset-password.js admin
